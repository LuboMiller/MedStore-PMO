## 1. Проблема / Контекст

**AS IS:** Усі медичні дані мережі «Добробут» (100 000+ пацієнтських візитів/місяць, ~30М документів за 10 років) зберігаються в операційній МІС «Доктор Елекс» (ДЕ) — великій ненормалізованій MSSQL-базі (~150М нод), документи у пропрієтарному закодованому форматі (HTML, стиснутий у бінарний).

**Чому зараз:** Клієнт має стратегічну потребу в когортній/семантичній аналітиці для дослідників і AI-ready інфраструктурі, але МІС це не підтримує. Внутрішнє бюджетне рішення клієнта заплановане на грудень 2026 — потрібен презентабельний Pilot до кінця листопада.

**Якщо не діяти:** Клієнт або вибере іншого підрядника, або відкладе проєкт. Devlight втрачає стратегічний E-Health контракт з потенціалом full-scale впровадження.

## 2. Мета

Реалізувати працездатний Discovery/Pilot v1 на реальних деперсоналізованих медичних даних ДЕ (~половина цільової функціональності MedStore + Query Interface), який клієнт самостійно протестує за узгодженим сценарним чек-листом, та надати data-driven оцінку бюджету й календаря повномасштабного впровадження — до кінця листопада 2026.

## 3. Критерії успіху

| # | Критерій | Метрика / Ціль | Дедлайн |
|---|---|---|---|
| 1 | Pilot v1 розгорнутий і self-tested | Клієнт прогнав узгоджені сценарії, бінарний pass | Кінець листопада 2026 |
| 2 | Де-ідентифікація ПІБ | Recall ≥ 99% на holdout-наборі (контрактний gate) | Кінець Discovery |
| 3 | Звіт якості пайплайна | recall@k, precision виміряні на golden set | Кінець Discovery |
| 4 | Full-scale scoping | Бюджетна + календарна оцінка повного впровадження з risk register | Кінець Discovery |
| 5 | Покриття типів шаблонів | Технічний звіт по DLL-вихлопу (% покритих типів/версій) | Тиждень 4–6 |

## 4. Scope

| Що входить | Що НЕ входить |
|---|---|
| Week-0 precondition: sandbox/реальний export | Повномасштабне впровадження (~30М документів) — окремий estimate |
| DLL export & ingest: обхід типів/версій, ETL, де-ідентифікація | Немедичні файли (Тип 3) — знижений пріоритет, фаза 2/3 |
| Pipeline: chunking/reranking/NER + recall/precision | SaaS / multi-client доступ («пріоритет номер два») |
| Бенчмарк моделей (embedder, реренкер, NER, local/cloud) | Live-інтеграція з МІС (лише нічна репліка) |
| De-identification: NER імен, holdout, fail-closed | Синоніми, діалогові сценарії — V1 |
| Golden set + каталог сценаріїв + критерії приймання | Юридична обробка за Законом про ПД |
| Pilot v1 deployment у пісочниці клієнта | Power BI дашборди (внутрішня справа клієнта) |
| Архітектура пілота, канонічна модель даних | Backup/DR стратегія (внутрішня справа клієнта) |
| Беклог V1, цілі V1, зв'язки з іншими системами | Довідник препаратів МНН/ATC мапінг (можливо перенесення на наступну фазу) |
| Бюджетна й календарна оцінка повного впровадження | |

**Тип контракту:** T&M (Додаток №3 до Framework Agreement №150626)

## 5. Обмеження

1. **Бюджет:** Baseline €70 633,50 (T&M); контрактний аванс як precondition для старту
2. **Таймлайн:** ~13 тижнів (оптимістичний); жорсткий зовнішній дедлайн — презентабельний Pilot до кінця листопада 2026 (бюджетне рішення клієнта в грудні)
3. **Технічні:** Читання лише з нічної reporting-репліки ДЕ; DLL-декодер — пропрієтарний бінарник (реверс-інжинірінг); FHIR R4/ICD-10/LOINC — preferred, не жорсткий gate
4. **Команда:** Обмежена вибірка (4 ролі, 1 Data/AI Engineer з об'єднаною роллю); Front-end — опційно
5. **Зовнішні AI:** LLM дозволені лише на деперсоналізованих даних; on-prem пріоритет (P1)
6. **Верифікація клієнтом:** Обмежені ресурси для spot-check (~100 документів)
