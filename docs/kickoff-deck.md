## Слайд 3 — Як ми розуміємо задачу

- **Проблема:** МІС «Доктор Елекс» не дає когортного / семантичного пошуку; дані у пропрієтарному форматі; AI-інструменти не підключити
- **Рішення:** MedStore — окреме деперсоналізоване сховище + Query Interface (когортний, по-пацієнтний, семантичний пошук)
- **Бізнес-результат:** Незалежність від МІС · дані як актив · AI-готовність · клінічна аналітика без залежності від ІТ
- *Спікер: «Підтвердіть, чи вірно розуміємо?»*

## Слайд 4 — Scope IN

1. **Доступ до даних та інджест:** контрольний зразок (топ-10 шаблонів) → повний реальний export; DLL decode; ETL з де-ідентифікацією
2. **Побудова пайплайна:** chunking/reranking/NER; бенчмарк моделей; вимір recall/precision
3. **Де-ідентифікація:** NER імен, holdout-набір, fail-closed правило; acceptance gate — recall ПІБ ≥ 99%
4. **Golden set:** узгоджений каталог лікарських запитів з критеріями приймання (бінарний результат)
5. **Pilot v1:** розгортання у пісочниці клієнта, self-test інтерфейс, прогін сценаріїв
6. **Full-scale scoping:** архітектура пілота, канонічна модель даних, скоуп + budget + calendar оцінка

## Слайд 5 — Scope OUT (обов'язково)

- Повномасштабне впровадження на ~30М документів (окремий estimate після Discovery)
- Немедичні файли (Тип 3) — знижений пріоритет, фаза 2/3
- SaaS / multi-client доступ
- Live-інтеграція з МІС (лише нічна репліка)
- Синоніми / діалогові / альтернативні формулювання — V1
- Юридична обробка за Законом про ПД
- Power BI дашборди (внутрішня справа клієнта)

- **Скрипт паузи:** «Чи є питання щодо цього переліку Out of Scope?»
- Підтвердження зафіксувати в Meeting Minutes → Decision Log
