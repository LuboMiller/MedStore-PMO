# Template — pmo-qg-review-wbs

### Вимір 1: Повнота і деталізація

Запитання: *Які блоки можуть бути недостатньо деталізовані? Що типово забувають?*

Перевір наявність:
- [ ] Project Management трек (планування, ризики, звітність, комунікація)
- [ ] Discovery / Architecture фаза
- [ ] QA як наскрізна активність (не тільки фінальне тестування)
- [ ] Infrastructure / DevOps / CI/CD
- [ ] App Store і Google Play submission process
- [ ] Документація (API docs, runbooks, user guides)
- [ ] UAT і stakeholder sign-off цикли
- [ ] Security audit / penetration testing
- [ ] Monitoring і alerting після launch
- [ ] Onboarding / training для клієнта
- [ ] Всі work packages ≤ 2 спринти

Формат findings:
```
| Severity | Блок | Проблема | Рекомендація |
|---|---|---|---|
| 🔴 / 🟡 / 🟢 | [назва] | [опис проблеми] | [конкретна дія] |
```

### Вимір 2: Нефункціональні вимоги (NFR)

Запитання: *Які нефункціональні вимоги не враховані у WBS?*

Перевір покриття:
- [ ] Performance (Lighthouse ≥ 85, API response time)
- [ ] Security (GDPR, платіжні системи, OAuth)
- [ ] Accessibility (якщо застосовно)
- [ ] Localization (не тільки переклад — формати дат, валют, адрес, VAT-розрахунки)
- [ ] Reliability / uptime (zero downtime legacy migration)
- [ ] Scalability (технічна готовність до ≥200 продавців)
- [ ] Observability (логування, трейсинг, алертинг)

Формат findings — той самий.

---

### Вимір 3: Залежності та критичний шлях

Запитання: *Де можуть виникнути вузькі місця? Затримка яких робіт зрушить весь проєкт?*

Аналіз:
1. Визнач логічні залежності між work packages (A не може стартувати без B)
2. Знайди ланцюжки де затримка одного блоку блокує декілька інших
3. Визнач work packages на критичному шляху до кожного milestone
4. Запропонуй варіанти паралелізації або розв'язки залежностей

Формат findings:
```
| Severity | Залежність | Ризик | Варіант розв'язки |
|---|---|---|---|
```

---

### Вимір 4: Ресурсне навантаження

Запитання: *Де перевантаження? Хто є single point of failure?*

Аналіз:
1. Зістав кожен work package з роллю(ями) з команди charter
2. Визнач місяці / спринти з піковим навантаженням на кожну роль
3. Знайди single point of failure (роль де відхід = блокер)
4. Визнач work packages що залежать від однієї особи (0.5 FTE ризики)

Формат findings — той самий.
